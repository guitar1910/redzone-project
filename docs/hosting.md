# RedZone — คู่มือขึ้นโฮสต์ (Deployment)

เอกสารนี้พาไปตั้งแต่รันบนเครื่องตัวเองด้วย XAMPP จนถึงเว็บที่คนอื่นเปิดได้จริง
ทุกขั้นตอนใช้ของฟรี ไม่ต้องผูกบัตรเครดิต

---

## 0. ระบบทำงาน 2 โหมด — ต้องเข้าใจก่อนอย่างอื่น

โค้ดชุดเดียวทำงานได้ทั้งสองโหมด และ**ตัดสินเองอัตโนมัติ**ตอนเปิดเว็บ
ไม่มีสวิตช์ให้ตั้ง ไม่ต้องแก้โค้ดตอนย้ายไปโฮสต์

| | โหมดต้นแบบ | โหมดจริง (live) |
|---|---|---|
| เกิดเมื่อ | เปิดไฟล์ตรง ๆ หรือใช้ Live Server (ไม่มี PHP) | เปิดผ่าน XAMPP หรือโฮสต์ที่รัน PHP ได้ |
| ข้อมูลอยู่ที่ | localStorage ของเบราว์เซอร์เครื่องนั้น | ฐานข้อมูล MySQL |
| คนอื่นเห็นข้อมูลเราไหม | **ไม่เห็น** แต่ละคนแยกกันคนละโลก | เห็น ใช้ข้อมูลชุดเดียวกันทุกคน |
| รหัสผ่าน | เทียบตรง ๆ ใน JavaScript | `password_verify()` ที่เซิร์ฟเวอร์ |
| เหมาะกับ | สาธิตเร็ว ๆ · เน็ตล่ม · โฮสต์ล่ม | ส่งอาจารย์ · ให้เพื่อนลองใช้ |

เช็กว่าอยู่โหมดไหน — เปิด Console (F12) พิมพ์ `RZ.LIVE`
ได้ `true` คือต่อฐานข้อมูลอยู่ · ได้ `false` คือโหมดต้นแบบ

> **ทำไมต้องมีสองโหมด** — วันนำเสนอถ้าโฮสต์ล่มหรือเน็ตมหาวิทยาลัยบล็อก
> ยังเปิดไฟล์จากเครื่องตัวเองสาธิตได้ทันที ไม่ต้องอธิบายว่า "ปกติมันใช้ได้นะครับ"

## 1. รันบนเครื่องตัวเองก่อน (XAMPP)

**ทำขั้นนี้ให้ผ่านก่อนขึ้นโฮสต์เสมอ** — บนเครื่องตัวเองแก้ปัญหาง่ายกว่าหลายเท่า
เพราะเห็น error log ได้ทันทีและไม่ต้องอัปโหลดไฟล์ใหม่ทุกครั้งที่แก้

1. ติดตั้ง [XAMPP](https://www.apachefriends.org/) แล้วกด **Start** ทั้ง Apache และ MySQL
2. คัดลอกโฟลเดอร์ `redzone-project` ไปไว้ใน `htdocs`
   - Windows : `C:\xampp\htdocs\redzone`
   - macOS : `/Applications/XAMPP/htdocs/redzone`
3. เปิด `http://localhost/phpmyadmin`
4. กด **Import** → เลือก `database/schema.sql` → Go
5. กด **Import** อีกครั้ง → เลือก `database/seed.sql` → Go
   **ต้องเรียงลำดับนี้** เพราะ seed อ้าง foreign key ที่ schema สร้างไว้
6. เปิด `http://localhost/redzone/`

ถ้าเห็นหน้าเข้าสู่ระบบและ Console พิมพ์ `RZ.LIVE` ได้ `true` = สำเร็จ

**บัญชีหลัง import — ล็อกอินได้บัญชีเดียว**

| ชื่อผู้ใช้ | ล็อกอินได้ | หมายเหตุ |
|---|---|---|
| `admin` | ✅ | รหัสผ่านอยู่ที่คุณคนเดียว ไม่ได้เขียนไว้ในไฟล์ใดของโปรเจกต์ |
| `user123` `user456` `user789` `user321` `user654` `user987` `user999` | ⛔ | เป็นแค่ข้อมูลตัวอย่างให้แผนที่และตารางผู้ใช้มีเนื้อหา รหัสผ่านถูกตั้งเป็นค่าสุ่มที่ไม่มีใครรู้ จึงล็อกอินไม่ได้ |

**ลืมรหัส admin ทำอย่างไร** — ตั้งใหม่ได้เสมอ (ดูข้อ 4.1) ไม่ต้องลบฐานข้อมูล

**อยากทดสอบเป็นผู้ใช้ทั่วไป** — กด "สมัครสมาชิก" ที่หน้าเข้าสู่ระบบ สร้างบัญชีใหม่เองได้เลย

### แก้ปัญหาที่เจอบ่อยบน XAMPP

| อาการ | สาเหตุและทางแก้ |
|---|---|
| MySQL กด Start แล้วดับทันที | พอร์ต 3306 ถูกโปรแกรมอื่นใช้ (มักเป็น MySQL ที่ติดตั้งแยกไว้) — ปิดตัวนั้น หรือเปลี่ยนพอร์ตใน XAMPP แล้วแก้ `DB_HOST` เป็น `127.0.0.1:พอร์ตใหม่` |
| Apache กด Start แล้วดับ | พอร์ต 80 ถูก IIS หรือ Skype ใช้ — เปลี่ยนพอร์ต Apache เป็น 8080 แล้วเปิด `http://localhost:8080/redzone/` |
| ภาษาไทยเป็น `à¸ªà¸¸à¸™` | import ด้วย charset ผิด — `schema.sql` มี `SET NAMES utf8mb4` อยู่แล้ว ถ้ายังเพี้ยนให้ลบฐานข้อมูลทิ้งแล้ว import ใหม่ ห้ามแก้ทีละแถว |
| `RZ.LIVE` เป็น `false` ทั้งที่เปิดผ่าน XAMPP | เปิดผิด URL (ใช้ `file://` หรือพอร์ตของ Live Server) ต้องเปิดผ่าน `http://localhost/...` |
| ขึ้น "เชื่อมต่อฐานข้อมูลไม่ได้" | ค่าใน `api/config/db.php` ไม่ตรง หรือยังไม่ได้ import ฐานข้อมูล |

## 2. เลือกโฮสต์

**สิ่งที่โฮสต์ต้องมี** (ขาดข้อใดข้อหนึ่งใช้ไม่ได้)

- PHP 8.0 ขึ้นไป พร้อมส่วนขยาย **PDO MySQL**
- MySQL หรือ MariaDB อย่างน้อย 1 ฐานข้อมูล
- **phpMyAdmin** หรือเครื่องมืออื่นสำหรับ import ไฟล์ `.sql`
- อัปโหลดไฟล์ได้ด้วย File Manager หรือ FTP
- รองรับ `.htaccess` (คือใช้ Apache ไม่ใช่ nginx) — ถ้าไม่รองรับ ยังใช้ได้แต่ต้องกันไฟล์ด้วยวิธีอื่น

**สิ่งที่โฮสต์ฟรีมักจำกัด** — เตรียมใจไว้

- เว็บถูกพักถ้าไม่มีคนเข้านานหลายวัน (เข้าครั้งแรกจะช้าสัก 10-20 วินาที)
- จำกัดจำนวน request ต่อวัน หรือจำกัดจำนวนการเชื่อมต่อฐานข้อมูลพร้อมกัน
- บางเจ้าแทรกโฆษณาในหน้าเว็บ — **ข้อนี้ควรเลี่ยง** เพราะงานส่งอาจารย์จะดูไม่ดี
- บางเจ้าลบบัญชีที่ไม่ได้ใช้งานเกิน 30-60 วัน → **สำรองไฟล์และฐานข้อมูลไว้เองเสมอ**
- บางเจ้าปิดฟังก์ชัน PHP บางตัว หรือไม่ให้ส่งอีเมล

> **ตรวจก่อนสมัคร** — เข้าหน้ารายละเอียดแพ็กเกจฟรีของเจ้านั้นแล้วดูว่ามี
> PHP · MySQL · phpMyAdmin ครบไหม และ**ต้องกรอกบัตรเครดิตหรือเปล่า**
> ถ้าหน้าสมัครขอเลขบัตร ให้ข้ามไปเจ้าอื่น
>
> ทางเลือกที่ควรถามก่อนไปหาโฮสต์ฟรี : **ขอพื้นที่จากคณะหรืออาจารย์**
> มหาวิทยาลัยหลายแห่งมี server ให้นักศึกษาทำโปรเจกต์ เร็วกว่า เสถียรกว่า และไม่มีโฆษณา

## 2.1 ถ้าใช้ InfinityFree — อ่านหัวข้อนี้

> ⚠️ ข้อมูลด้านล่างมาจากความรู้ทั่วไปเรื่องโฮสต์ฟรีลักษณะนี้ **เงื่อนไขของผู้ให้บริการ
> เปลี่ยนได้ตลอด** ให้ยืนยันกับหน้าเว็บและ control panel จริงตอนสมัครทุกครั้ง
> ถ้าเจอไม่ตรงกับที่เขียนไว้ ให้เชื่อของจริงและบอกให้แก้เอกสารนี้

### สิ่งที่ต้องทำต่างจากคู่มือหลัก 4 ข้อ

**1. ห้าม import `schema.sql` กับ `seed.sql` ตัวเดิม — ใช้ไฟล์ `-hosting` แทน**

โฮสต์ฟรีไม่ให้เว็บสร้างฐานข้อมูลเอง (ต้องสร้างจาก control panel) ไฟล์เดิมมีคำสั่ง
`CREATE DATABASE` กับ `USE redzone;` อยู่ จะขึ้น error ทันที

ในโฟลเดอร์มีไฟล์ที่ตัดสองคำสั่งนั้นออกให้แล้ว **ใช้คู่นี้**

```
database/schema-hosting.sql     ← import ไฟล์นี้ก่อน
database/seed-hosting.sql       ← แล้ว import ไฟล์นี้ต่อ
```

**2. ค่าเชื่อมต่อฐานข้อมูลไม่ใช่ localhost**

โฮสต์จะตั้งชื่อให้เองและมักมีคำนำหน้า (prefix) ติดมา หน้าตาประมาณนี้

| ค่า | ตัวอย่างที่โฮสต์ให้ | เอาไปใส่ที่ |
|---|---|---|
| ชื่อเซิร์ฟเวอร์ฐานข้อมูล | `sql123.xxxxx.com` | `DB_HOST` |
| ชื่อฐานข้อมูล | `if0_12345678_redzone` | `DB_NAME` |
| ชื่อผู้ใช้ | `if0_12345678` | `DB_USER` |
| รหัสผ่าน | (ที่ตั้งไว้ตอนสร้าง) | `DB_PASS` |

**คัดลอกมาวางทั้งค่า** รวมคำนำหน้า `if0_...` ห้ามตัดออก — ลืมคำนำหน้าคือสาเหตุ
ที่คนติดกันมากที่สุด แล้วจะขึ้นข้อความ "เชื่อมต่อฐานข้อมูลไม่ได้"

**3. อัปโหลดลงโฟลเดอร์ `htdocs` เท่านั้น**

โฮสต์ฟรีมักมีโฟลเดอร์อื่นปนอยู่ (`.htpasswd`, ไฟล์ระบบ) **ห้ามลบของเดิม**
เอาไฟล์เราลงใน `htdocs` และถ้ามี `index2.html` หรือหน้าโฆษณาของโฮสต์อยู่ ให้ลบเฉพาะไฟล์นั้น

ไฟล์เยอะพอสมควร (ประมาณ 40 ไฟล์) **อัปโหลดผ่าน File Manager บนเว็บจะช้าและหลุดง่าย**
แนะนำใช้โปรแกรม FTP เช่น **FileZilla** (ฟรี) ด้วยค่า FTP ที่โฮสต์ให้ — เร็วกว่าและ
ไม่หลุดกลางทาง ถ้าโฮสต์รองรับการอัปโหลดไฟล์ zip แล้วแตกไฟล์บนเซิร์ฟเวอร์ ก็ใช้วิธีนั้นได้

**4. เรื่อง `.htaccess` — เตรียมไว้ให้แล้ว ไม่ต้องแก้**

โฮสต์ฟรีหลายเจ้าไม่ได้ใช้ Apache แบบ mod_php (มักเป็น LiteSpeed) ซึ่งคำสั่ง `php_flag`
จะใช้ไม่ได้และ**ทำให้เว็บตอบ 500 Internal Server Error ทั้งเว็บ**

ไฟล์ `.htaccess` ทุกไฟล์ในโปรเจกต์นี้ห่อคำสั่งพวกนั้นไว้ใน `<IfModule>` แล้ว
เซิร์ฟเวอร์ที่ไม่รองรับจะข้ามไปเงียบ ๆ ไม่ error

**แต่ถ้าเปิดเว็บแล้วขึ้น 500 ทั้งเว็บ** ให้ลองเปลี่ยนชื่อ `.htaccess` เป็น `htaccess.txt`
ชั่วคราว ถ้าเว็บกลับมาได้ = ปัญหาอยู่ที่ไฟล์นี้ แล้วบอกมาเพื่อแก้ให้ตรงกับโฮสต์นั้น

### ข้อจำกัดของโฮสต์ฟรีที่ต้องเตรียมใจ

- **มีด่านตรวจว่าเป็นคนหรือบอท** — บางเจ้าแทรกหน้าตรวจสอบก่อนเข้าเว็บครั้งแรก
  ซึ่งอาจทำให้คำขอของ `fetch()` ในเว็บเราถูกบล็อกได้ **ข้อนี้ต้องทดสอบก่อนอย่างอื่น**
  (ดูวิธีตรวจในข้อ 3.5) ถ้าเจอปัญหานี้ วิธีแก้อยู่ที่ control panel ของโฮสต์
- **จำกัดจำนวนคนเข้าต่อวัน** และจำกัดการใช้ CPU — พอสำหรับงานส่งอาจารย์
- **เว็บถูกพักถ้าไม่มีคนเข้านานหลายวัน** เข้าครั้งแรกจะช้า 10-20 วินาที
  **ก่อนวันนำเสนอให้เข้าเว็บเช็กหนึ่งรอบ** อย่าเปิดครั้งแรกหน้าห้อง
- **บัญชีถูกลบถ้าไม่ใช้งานนาน** — Export ฐานข้อมูลเก็บไว้เสมอ (ข้อ 5)
- ส่งอีเมลจากเว็บไม่ได้ (ระบบเราไม่ได้ใช้ จึงไม่กระทบ)

## 3. อัปโหลดขึ้นโฮสต์

### 3.1 ไฟล์ที่ต้องอัปโหลด

อัปโหลดทุกอย่างลงในโฟลเดอร์เว็บของโฮสต์ (ชื่อมักเป็น `htdocs` หรือ `public_html`)

```
index.html
.htaccess          ★ ห้ามลืม ไม่มีไฟล์นี้ไฟล์ความลับจะเปิดอ่านได้จากเบราว์เซอร์
assets/            (css, js, img)
api/               (รวม api/config/.htaccess)
uploads/           (รวม uploads/.htaccess)
```

### 3.2 ไฟล์ที่ **ไม่ควร** อัปโหลด

| ไฟล์ | เหตุผล |
|---|---|
| `database/` | `seed.sql` มี hash รหัสผ่านของทุกบัญชี และ `schema.sql` บอกโครงสร้างตารางทั้งระบบ — import จากเครื่องตัวเองผ่าน phpMyAdmin แทน |
| `docs/` | เอกสารภายใน ไม่ต้องเปิดให้คนนอกอ่าน |
| `README.md` | มีรหัสผ่านตั้งต้นเขียนอยู่ |

> ถ้าเผลออัปโหลดขึ้นไปแล้ว `.htaccess` จะกันการเปิดไฟล์ `.sql` และ `.md` ไว้ให้อีกชั้น
> แต่**อย่าพึ่งแค่ชั้นนี้** — ไม่อัปโหลดตั้งแต่แรกปลอดภัยกว่า และถ้าโฮสต์ใช้ nginx
> ไฟล์ `.htaccess` จะไม่ทำงานเลย

### 3.3 สร้างฐานข้อมูลบนโฮสต์

1. เข้า control panel ของโฮสต์ → สร้างฐานข้อมูล MySQL ใหม่
2. **จดค่า 4 ตัวนี้ไว้** โฮสต์มักตั้งชื่อให้เองไม่ใช่ `redzone`
   - ชื่อโฮสต์ฐานข้อมูล (เช่น `sql123.hostname.com` — **มักไม่ใช่** `localhost`)
   - ชื่อฐานข้อมูล
   - ชื่อผู้ใช้ฐานข้อมูล
   - รหัสผ่านฐานข้อมูล
3. เปิด phpMyAdmin ของโฮสต์ → เลือกฐานข้อมูลที่สร้าง → **Import** → `database/schema-hosting.sql`
4. **Import** → `database/seed-hosting.sql` ต่อ

   ★ ใช้ไฟล์ที่ลงท้าย `-hosting` เท่านั้น ไฟล์ `schema.sql` / `seed.sql` ตัวเดิม
   มีคำสั่ง `CREATE DATABASE` ซึ่งโฮสต์ฟรีไม่อนุญาต จะขึ้น error
   (ไฟล์ตัวเดิมใช้กับ XAMPP บนเครื่องตัวเอง)

### 3.4 ตั้งค่าการเชื่อมต่อ

แก้ `api/config/db.php` ให้เป็นค่าของโฮสต์

```php
define('DB_HOST', 'sql123.hostname.com');   // ค่าที่โฮสต์ให้ ไม่ใช่ localhost
define('DB_NAME', 'ชื่อฐานข้อมูลที่โฮสต์สร้าง');
define('DB_USER', 'ชื่อผู้ใช้ที่โฮสต์ให้');
define('DB_PASS', 'รหัสผ่านที่โฮสต์ให้');
```

**ห้ามใช้ `root` รหัสว่างบนโฮสต์เด็ดขาด** — นั่นคือค่าของ XAMPP บนเครื่องตัวเองเท่านั้น

### 3.5 ตรวจว่าใช้ได้

เปิดเว็บที่โฮสต์ให้มา แล้วตรวจตามลำดับนี้

1. เห็นหน้าเข้าสู่ระบบ (ถ้าเห็นโค้ด PHP เป็นตัวหนังสือ = โฮสต์ไม่รัน PHP ใช้ไม่ได้)
2. **ข้อที่สำคัญที่สุด** — กด F12 เปิด Console พิมพ์ `RZ.LIVE` แล้ว Enter

   | ได้ค่า | หมายความว่า | ต้องทำอะไร |
   |---|---|---|
   | `true` | ต่อฐานข้อมูลได้ ✅ | ไปข้อ 3 ต่อ |
   | `false` | **PHP ยิงไม่ถึงหรือถูกบล็อก** | เปิดแท็บ Network ใน F12 แล้วรีเฟรช ดูว่า `api/bootstrap.php` ตอบอะไร |

   ถ้า `bootstrap.php` ตอบมาเป็นหน้า HTML แปลก ๆ แทน JSON = โฮสต์แทรกด่านตรวจบอทอยู่
   ถ้าตอบ 500 = ปัญหาที่ `.htaccess` หรือค่าใน `db.php`
   ถ้าตอบ 404 = อัปโหลดโฟลเดอร์ `api/` ไม่ครบ
3. ล็อกอิน `admin` → เข้าฝั่งผู้ดูแลระบบได้ เห็นคิวรอตรวจ 4 ใบ
4. เปิดจาก**มือถือหรือเครื่องเพื่อน** ล็อกอินบัญชีอื่น → ต้องเห็นข้อมูลชุดเดียวกัน
5. ลองเปิด `เว็บของคุณ/database/seed.sql` → **ต้องขึ้น 403 Forbidden** ถ้าเปิดอ่านได้คือ `.htaccess` ไม่ทำงาน

## 4. ★ ต้องทำทันทีหลังขึ้นโฮสต์ — เรื่องความปลอดภัย

### 4.1 ตั้งรหัสผ่าน admin เป็นของตัวเอง

รหัสที่มาพร้อมไฟล์เป็นค่าสุ่มที่ส่งให้คุณครั้งเดียว **ควรเปลี่ยนเป็นรหัสที่คุณจำได้เอง**
และถ้าลืมก็ใช้วิธีเดียวกันนี้ตั้งใหม่ได้ตลอด

สร้าง hash ใหม่บนเครื่องตัวเอง (ที่มี XAMPP)

```bash
php -r "echo password_hash('รหัสใหม่ของคุณ', PASSWORD_DEFAULT);"
```

เอาค่าที่ได้ไปสั่งใน phpMyAdmin ของโฮสต์

```sql
UPDATE users SET password_hash = '<ค่าที่ได้>' WHERE username = 'admin';
```

บัญชีตัวอย่างอีก 7 บัญชีล็อกอินไม่ได้อยู่แล้ว (รหัสเป็นค่าสุ่มที่ไม่มีใครรู้)
ถ้าอยากลบออกให้แผนที่เหลือแต่ข้อมูลจริง สั่งได้เลย — รายงานของคนพวกนี้จะหายไปด้วย

```sql
DELETE FROM users WHERE username IN
  ('user123','user456','user789','user321','user654','user987','user999');
```

### 4.2 เปิด HTTPS

โฮสต์ฟรีส่วนใหญ่มี SSL ฟรีให้ (Let's Encrypt) เปิดใน control panel
**สำคัญเพราะ** ถ้าเป็น `http://` ธรรมดา รหัสผ่านที่ผู้ใช้กรอกจะวิ่งผ่านเน็ตเป็น
ข้อความเปล่า ใครดักดูใน Wi-Fi เดียวกันก็อ่านได้

### 4.3 ตรวจว่ากันไฟล์ความลับได้จริง

ลองเปิด URL พวกนี้จากเบราว์เซอร์ **ทุกอันต้องขึ้น 403 หรือ 404**

```
เว็บของคุณ/api/config/db.php
เว็บของคุณ/database/seed.sql
เว็บของคุณ/README.md
เว็บของคุณ/assets/            (ต้องไม่เห็นรายชื่อไฟล์)
```

ถ้าอันไหนเปิดอ่านได้ = โฮสต์ไม่รองรับ `.htaccess` ต้องย้ายไฟล์นั้นออกจากโฟลเดอร์เว็บ

### 4.4 สิ่งที่ระบบทำไว้ให้แล้ว (อธิบายอาจารย์ได้)

| เรื่อง | ทำที่ไหน |
|---|---|
| รหัสผ่านเก็บเป็น hash เท่านั้น | `password_hash()` ใน `api/register.php` |
| ตรวจรหัสผ่านที่เซิร์ฟเวอร์ | `password_verify()` ใน `api/auth.php` |
| ข้อความ error ตอนล็อกอินผิดเหมือนกันหมด | ไม่บอกว่าชื่อผู้ใช้ไหนมีในระบบ |
| กัน SQL Injection | ใช้ PDO prepared statement ทุก query ไม่มีการต่อ string เข้า SQL |
| กัน session fixation | `session_regenerate_id(true)` ตอนล็อกอินสำเร็จ |
| ตรวจสิทธิ์ทุก endpoint | `require_login()` และ `require_role('admin')` |
| ไม่ให้สมัครเป็น admin | `register.php` เขียน `role='user'` ตายตัว ไม่รับค่าจากผู้ใช้ |
| ไม่ส่งชื่อผู้แจ้งให้คนที่ไม่เกี่ยวข้อง | กรองใน `api/bootstrap.php` ก่อนส่งออก |
| ตรวจขอบเขต 10 กม. ที่เซิร์ฟเวอร์ | Haversine ใน `api/reports.php` |
| ไม่รันไฟล์ในโฟลเดอร์ uploads | `uploads/.htaccess` |
| ไม่แสดง error ให้ผู้ใช้เห็น | `display_errors off` + `set_exception_handler` ใน `db.php` |
| **กัน XSS** — ข้อความผู้ใช้ถูกแปลงก่อนใส่ HTML ทุกจุด | `RZ.esc()` ใน `assets/js/utils.js` |
| **คุกกี้ session** HttpOnly + SameSite=Lax (+ Secure เมื่อเป็น https) | `session_set_cookie_params()` ใน `db.php` |
| **CSRF token** ทุกคำขอที่เปลี่ยนข้อมูล | `csrf_token()` / `require_csrf()` ใน `db.php` |
| **จำกัดล็อกอินผิด** 8 ครั้งใน 15 นาที | ตาราง `login_attempts` + ตรวจใน `api/auth.php` |
| กัน timing attack ตอนล็อกอิน | เรียก `password_verify()` เสมอ แม้ไม่มีชื่อผู้ใช้นั้น |

### 4.5 สิ่งที่ยังไม่ได้ทำ — พูดตรง ๆ ดีกว่าให้อาจารย์จับได้

| เรื่อง | ความเสี่ยง | ทำได้อย่างไรถ้าจะทำต่อ |
|---|---|---|
| ยืนยันตัวตนว่าเป็นคน มจพ. จริง | ใครก็สมัครด้วยรหัสนักศึกษาของคนอื่นได้ | ส่งลิงก์ยืนยันไปที่อีเมลมหาวิทยาลัย ก่อนเปิดใช้บัญชี |
| รหัสผ่านต้องยาว 8 ตัวเท่านั้น ไม่ตรวจความแข็งแรง | `12345678` ผ่านได้ | เทียบกับรายการรหัสผ่านยอดนิยม และบังคับความยาวขึ้น |
| ไม่มีลืมรหัสผ่าน | ผู้ใช้ที่ลืมรหัสต้องรบกวนแอดมิน | ส่งลิงก์รีเซ็ตที่มีอายุจำกัดไปทางอีเมล |
| อัปโหลดรูปประกอบรายงาน | ยังทำไม่ได้ (แต่ `uploads/.htaccess` กันไว้แล้ว) | ตรวจชนิดไฟล์จากเนื้อไฟล์ · เปลี่ยนชื่อไฟล์ · จำกัดขนาด |
| สำรองฐานข้อมูลอัตโนมัติ | โฮสต์ฟรีลบบัญชีได้ทุกเมื่อ | Export เองก่อนวันส่ง (ดูข้อ 5) |
| Security header (CSP, X-Frame-Options) | ลดผลกระทบถ้ามีช่องโหว่หลุด | เพิ่มใน `.htaccess` |

**บั๊กความปลอดภัยที่เคยมีจริงในโค้ดนี้ และแก้แล้ว** — เอาไปเล่าในรายงานได้ อาจารย์ชอบ

1. **Stored XSS ที่ tooltip แผนที่** — ข้อความในช่อง "อื่น ๆ (ระบุเอง)" ถูกใส่เป็น HTML
   ผู้ใช้พิมพ์ `<img src=x onerror=...>` ได้ แล้วสคริปต์รันในเบราว์เซอร์ของ**ทุกคน**
   ที่เปิดแผนที่ รวมถึงแอดมิน = ยึดบัญชีแอดมินได้ · แก้ด้วย `RZ.esc()`
2. **stack trace หลุดออกหน้าเว็บ** — error ของ PHP พิมพ์ path เต็มของเซิร์ฟเวอร์ให้คนอ่าน
3. **ส่งชื่อผู้แจ้งให้คนที่ไม่เกี่ยวข้อง** — ในระบบแจ้งเหตุคุกคาม ทำให้ผู้แจ้งถูกตามไปคุกคามซ้ำได้
4. **`database/seed.sql` เปิดอ่านจากเบราว์เซอร์ได้** — เห็น hash รหัสผ่านทุกบัญชี

## 5. สำรองข้อมูลก่อนวันนำเสนอ

โฮสต์ฟรีล่มหรือลบบัญชีได้ทุกเมื่อ **ทำสองอย่างนี้ก่อนวันส่ง**

1. phpMyAdmin → **Export** → เลือก SQL → เก็บไฟล์ไว้ในเครื่องและใน Google Drive
2. เก็บสำเนาโฟลเดอร์โปรเจกต์ทั้งชุดไว้ พร้อมเปิดโหมดต้นแบบสาธิตได้ทันที

**แผนสำรองวันนำเสนอ** — ถ้าโฮสต์เข้าไม่ได้ เปิดโฟลเดอร์บนเครื่องตัวเอง
ระบบจะถอยไปโหมดต้นแบบเองอัตโนมัติ สาธิตครบทุก use case ได้เหมือนเดิม
บอกอาจารย์ตรง ๆ ว่าออกแบบให้ทำงานได้สองโหมดโดยเจตนา — เป็นข้อดีของงาน ไม่ใช่ข้ออ้าง
